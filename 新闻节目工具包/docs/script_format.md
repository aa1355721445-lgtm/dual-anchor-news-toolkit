# 稿子格式（稿子.md）

稿子既是给人看的台本，也是流水线的输入。`pipeline.py parse` 读它，`dub` 从它生成配音稿，`stage` 从它生成分镜。
**写完先跑 `parse`，没有 ⚠ 再交给用户。** parse 会检查：标记名、表情名、镜头、特效、各种 @锚点是否真的在台词里。

## 一、写稿之前必须读的东西

1. 主播人设档案（`show.json → style_file`）：两位主播的说话方式、自称、口头禅、关系。有人物卡 JSON（`hosts.X.card`）就完整读一遍，照卡里的说话方式和示例对话写；两者冲突时以用户指定的为准。和节目无关的设定（恋爱、私生活）不写。
3. 术语对照（`show.json → terms_file`）：游戏内叫法 → 口播叫法。新版本出现的新叫法，写稿后补进这张表。
4. 本期的关键点汇总（字幕 + 截图核对过的事实）。**稿子里每个数字、日期、名字都要能在汇总里找到出处。**

## 二、节目定位（默认值，show.json 的 `format` 可覆盖）

- 新闻播报：主播 A 负责串场和情绪，主播 B 负责把资讯讲清楚（按 `format` 改）。
- 梗少一点。想加梗的位置先写一行 `【梗位：想法】`，和用户讨论后再落成台词（解析时这行会被跳过）。
- 「配队建议」这类需要看别人视频才能定的内容，先写 `【配队建议：待定】` 占位（同样会被跳过），或放到文末 `## 待讨论`。
- 板块顺序参考 `show.json → sections`（版本前瞻常见：开场提要 → 福利与活动 → 新角色 × N → 新内容 → 优化与调整 → 结尾）。其他内容自己定板块，但每期都要有开场和结尾。
- 涉及抽卡、付费的内容只讲事实（什么时候开、能拿多少），**不劝抽、不给消费建议**。
- 长度参考：5–7 分钟成片 ≈ 50 句左右、每句 1–3 个短句。单句别超过 ~60 字，长信息拆成两人接力。

## 三、口播用词

- 稿子里可以写阿拉伯数字（`20 抽`、`9 月 24 号`、`2.1`），`dub` 会自动转成汉字给配音（`二十抽`、`九月二十四号`、`二点一`），字幕也显示汉字版。
- 量词前的 2 读「两」（两个、两抽、两百万），「第 2」读「第二」；`50%`→百分之五十；`2026 年`→二零二六年；`1v1`→一对一。
- **分数、斜杠日期（9/24）、英文缩写（UP、PV、CV）、带单位的符号**不会自动转，直接写成想让配音念的汉字（如「九月二十四号」「限定池是」）。
- 跑完 `dub` 打开配音稿通读一遍，确认念法。
- 书名号、引号会在配音稿里去掉（《》保留），所以别靠引号表达语气。
- 游戏内专有名词先查术语对照，玩家不这么叫的就换成口语说法。

## 四、标记语法

```markdown
# 节目名 版本「副标题」            ← 一级标题随意，不解析
> 引用行随意写说明，不解析

## 板块名 · 副标题                 ← 二级标题 = 一个板块（出转场 + 下方栏目名）

🎬 18:33–18:47                     ← 下一句开始，大屏播原视频 18:33 起的画面
A：【镜头:全景】【贴纸:得意】各位观众，晚上好！
B：（翻稿子）今天的重点……         ← （ ）里是动作提示，不念、不上字幕，但会用来自动选表情
```

### 说话人
`A：` / `**A**：` / `主播A：` —— 主播名字或 `show.json → hosts.X.aliases` 里的简称，全角或半角冒号都行（下文例子里 A、B 换成你的主播简称）。一行一句，同一个人连说两段就写两行。

### 片段（大屏）
| 写法 | 意思 |
|---|---|
| `🎬 MM:SS–MM:SS` | 下一句开始推进大屏，播原视频这一段（结束时间只是参考，实际播放长度按台词算） |
| `🎬 MM:SS–MM:SS 原声 说明` | 同上，并且成片里保留这段原视频的声音（规则见下） |
| `🎬 37:01 → 37:17@版本更新后 → 37:33@下半开池以后` | 一句话里换画面：说到「版本更新后」这几个字时切到 37:17 |
| `🎬 续` | 下一句继续停在大屏上（片段接着播），没有这行的话，无 🎬 的句子会拉回演播室 |
| `🎬 关`（或 `🎬 无`） | 明确回到演播室 |
| 时长超过 1 小时 | `1:02:33` |

一句话没写 🎬，镜头就回到两位主播。挑哪段画面、每段多长、怎么播，见 hosts_and_footage.md 第三节「选实机画面的细则」。连续几句都写了 🎬 会一直留在大屏，只换画面。

### 原声规则（默认，`show.json → audio.orig_rule`）
- 建议**不留 PV 音乐**（背景音乐后期统一配，也避免版权问题）。
- 只在**没有官方讲解**的时段留：实机音效、角色语音。
- 先用 `speechmap` 查原视频里连续 ≥3 秒没讲解的时段，再在这些时段里挑画面。`speechmap` 也会检查标了原声的片段被官方讲解覆盖了多少（>30% 要换）。
- 配音期间原声自动压低（ducking），需要让原声单独先响几秒，就在那句加 `【独奏:秒数】`。

### 行内标记（全部写在【】里，不念）
写在句首 = 这句一开始生效；写在句子中间 = 说到那个位置时生效。

| 标记 | 例子 | 作用 |
|---|---|---|
| `【贴纸:表情】` | `【贴纸:吃惊】` | 说话人换表情。可用表情名见 `show.json → hosts.X.emotions`（也可以直接写贴纸编号如 `06_surprised`）。想要表里没有的表情/动作就照写，跑 `stickers` 会列进贴纸需求让用户新画（整张图，不分部件） |
| `【反应:表情】` | A 的句子里写 `【反应:吃惊】` | 写在说话人的句子里，改的是**另一位**主播（听的人）的表情，所以表情名要从**另一位**的表情表里选 |
| `【镜头:…】` | 全景 / 特写 / 倾斜 / 推近 / 特写B | 特写=对准说话人；特写+名字或简称（如「特写B」）=对准指定主播（拍听的人的反应）；倾斜=倾斜特写（吐槽、生气）；推近=慢推（正经、收尾）。不写时按规则自动选。在大屏上的句子镜头不起作用 |
| `【特效:…】` | `【特效:拍桌、感叹】` | 拍桌、闪光、速度线、冲击、汗、问号、感叹、生气、脸红、闪亮，可多个，用顿号分隔。长什么样由你的包装决定（package_rules.md），素白版只标出名字 |
| `【要点:文字@锚点\|颜色】` | `【要点:白送 20 抽@二十抽\|gold】` | 主播旁边弹出要点贴纸。`@锚点`=说到这几个字时弹出（写口播里的原字，数字写汉字版也行）；不写锚点就在标记所在位置弹出。颜色：gold pink blue mint purple red，可省略 |
| `【信息牌:文字】` | `【信息牌:上半 · 3 月 1 日开启】` | 大屏放画面时右上角的信息牌（` · ` 分上下两行；文字带「晴」显示太阳，带「多云」加云朵；`【天气:…】` 是同一个东西） |
| `【独奏:秒】` | `【独奏:2.8】` | 这句前面先空出几秒，只放大屏原声 |
| `【收屏@锚点】` | `【收屏@总之】` | 说到「总之」时从大屏闪回演播室（同一句前半在大屏、后半在演播室）。只能用在大屏上的句子。也可写 `【收屏:总之】` |
| `【梗位：…】` `【配队建议：…】` | 单独一行 | 讨论用占位，不进成片 |

要点贴纸每句 0–3 个，一个片段最多同时 3 个。别把整句话做成贴纸，只放数字、名字、结论。

### 不念的空动作句
`A：（举起拳头）【贴纸:握拳】【特效:闪光、速度线】` —— 冒号后面没有台词，只做一个 1.8 秒的动作镜头，适合片尾。

### 停止解析
遇到 `## 术语` / `## 待讨论` / `## 附录` / `## 备注` 这类标题，后面都不解析，可以放讨论内容。

## 五、自检清单（交稿前）
- [ ] `parse` 没有 ⚠（锚点打错字也会报）
- [ ] 每个事实在关键点汇总里有出处；日期、抽数、名字核对过截图（AI 字幕同音错字很多）
- [ ] 两人的口癖、自称符合人设档案，没有串到对方身上
- [ ] 每段 🎬 的时间点在原视频里确实是对应画面，不是官方主持人的脸
- [ ] 原声段都在「没讲解」的时段，且符合 `audio.orig_rule`
- [ ] 梗位、配队建议这类待定内容已标出，等用户确认

## 六、看点速报（可选，每期最前面）

想要的话，整期的第一个板块写成 `## 看点速报`，放在片头之前，一上来就把爆点抛出来。时间线和代码见 hook_rules.md。

**写法规范**
- 总长 20–30 秒：4–6 条看点 + 1–2 句收尾。
- **两人轮流说**，一人一条；按各自性格分配反应（一个大惊小怪、一个惊喜之类）。
- 一条只说一个爆点，一句话说完，主体不超过 18 个字；只抛结论，细节留给正片。
- 句式以「什么？！＋爆点」为主，至少换一两种说法（「竟然…」「还能…」「等等——」），别六条全一样。
- **只从本期正片里挑**：速报里说的，正片里必须讲到。
- 挑选顺序：白送的福利 > 新角色亮点 > 新地图 / 大玩法 > 有反差、能玩梗的名场面。数字必须准确；可以打比方，但不能说成官方没说过的事。
- 排序：第一条放最炸的；中间节奏快；最后一条放好玩或有悬念的（最好是正片里的名场面）。
- 收尾每期换着说，意思是「本期细节都在后面，请继续观看」，例如「这些本期都会一条条讲清楚——精彩内容，请继续观看！」「想知道细节？那就继续往下看！」
- 语气比正片更急、更兴奋；可以比正片多一点情绪和梗，但事实不能夸大。

**标记**
- 每条看点前面照常写 🎬 时间点（包装层拿到这段实机画面）；没写 🎬 的看点是「悬念」模式。
- `【气泡:什么？！】`：主播的震惊气泡文字。不写时自动取句首的「什么？！」「竟然？！」「等等！」之类；想不要气泡就写 `【气泡:】`。
- `【要点:…】`：在看点速报里不写锚点也会在这句一开始就弹出。
- `【收尾】`：标在收尾那句（从这句起进入收尾模式）。含「继续观看 / 往下看」的句子会自动算收尾。

**示例**
```markdown
## 看点速报

🎬 37:01–37:12
A：【贴纸:吃惊】什么？！这个版本白送 20 抽？！【要点:白送 20 抽|gold】

🎬 18:40–19:10
B：【贴纸:开心】【气泡:竟然？！】竟然开了一整座游乐园？！【要点:新地图：游乐园|mint】

A：【贴纸:生气】【特效:生气】还有——这个新角色怎么回事？！

B：【贴纸:得意】【收尾】这些本期都会一条条讲清楚。
A：【贴纸:指】【特效:闪光】精彩内容——请继续观看！

## 开场 · 内容提要
……
```
