# 双主播资讯节目 · 一条龙（通用版）

用户说「做一期前瞻」「出一期活动速报」「把这个 PV 做成节目」之类，就用这个流程。
成品：（可选）开头「看点速报」→ 片头 → 演播室里两位主播（用户自己的贴纸）播报，镜头推进大屏播官方画面，配字幕、要点贴纸、音效；外加 16:9 / 4:3 封面和章节时间点。

这是**通用版**：流程、对齐、分镜、渲染引擎都是现成的；**主播贴纸、演播室场景、节目包装（台标、新闻栏、转场、片头、看点速报画面、灯光、特效）由用户自己做**。通用版里这些位置是：
- 主播：没有贴纸时用占位小人（一眼能看出是占位）。
- 场景：自带一个中性的示例演播室，用户可换成自己的图片或代码（docs/scene_rules.md）。
- 包装：素白占位（白字黑底），能跑通出片，用户按 docs/package_rules.md 换成自己的设计。

## 0. 找到工具包和节目包（每次先做）

- **第一次用、换电脑、收到新安装包、或用户问「还缺什么」**：先跑 `python <工具包>/scripts/pipeline.py setup`。它会解压项目文件夹里的安装包、整理工作区分区（工具包 / 节目包 / 每期文件夹 / 安装包存档）、检查环境和节目包、写 `工作区.json`、列出还缺什么和下一步。把结果用几句话告诉用户，能自动补的直接补（`--install`），要用户动手的说清楚怎么做。工具包出新版时 `setup --update`（只更新工具，节目包永不覆盖）。
- **新用户的节目包是模板**：节目名、主播名、表情表都是占位。第一次要陪用户把这些定下来（docs/config.md「从模板开始」），再跑 `scene --show <节目包>` 看看场景。
- **工具包** `新闻节目工具包/`（scripts、engine、templates、docs）和 **节目包** `节目包/`（show.json、贴纸、场景、包装、品牌、人物卡、术语对照）都在用户的项目文件夹里（看 `工作区.json`）。找不到就问用户在哪。每期一个文件夹，例如 `第1期/`。
- 细节都在工具包的 `docs/`，**用到哪步读哪篇**（`docs/流水线完整说明.md` 是给人通读的总说明，`docs/流程图.html` 是流程图）：
  - `workflow.md`：初始化、步骤、本机/云端、截片段、渲染、交付（**第一次用先通读**）
  - `config.md`：show.json / episode.json，从模板开始、换主播、换游戏
  - `scene_rules.md`：演播室场景——示例场景、图片场景、代码场景、场景编辑器、`scene` 预览和导出（**做场景前必读**）
  - `package_rules.md`：节目包装——每一层在哪个函数、什么时候出现、能拿到什么数据、设计时要守的硬约束（**做包装前必读**）
  - `sourcing_bilibili.md`：在 B 站找视频、拿字幕、截图
  - `script_format.md`：稿子格式和写稿规则，第六节是看点速报（**写稿前必读**）
  - `hosts_and_footage.md`：主播站位和镜头、实机画面怎么截/怎么播（**写 🎬 前必读**）
  - `staging_rules.md`：自动分镜、对齐、声音规则
  - `animation_rules.md`：主播随配音的弹性拉伸、换表情弹跳、摄像机运动和调参
  - `hook_rules.md`：看点速报的结构和时间线
  - `qa_checklist.md`：交付前检查（**交付前必过**）

## 1. 选运行位置：优先本机，不行走云端

- 能在用户电脑上执行命令时，在本机跑：先 `setup`，全绿就全程本机。
- 本机 shell 起不来就别反复试，改在云端工作区跑：把工具包、节目包、本期文件夹拷进工作区，保持同样的相对结构，跑 `setup --root <工作区副本> --install`；原视频太大拷不进来时，片段让用户在本机用生成的 `截片段.ps1` 截。云端交付时单文件有大小上限，`episode.json` 里 `split_mb` 填上限（例如 29）。

## 2. 步骤（⏸ = 必须停下等用户）

命令：`python3 <工具包>/scripts/pipeline.py <命令> --ep <本期文件夹>`（Windows 用 `python`；**脚本和 --ep 都写绝对路径**；全部参数见 workflow.md 开头的表）

0. **节目只做一次**：定节目名、两位主播（名字、简称、颜色、表情表）、场景（`scene` 预览）、包装（先用素白占位也能出片）。见 config.md / scene_rules.md / package_rules.md。
1. **建期**：`init --ep <本期> --show <节目包> --version 2.1`，按提示改 `episode.json` 的占位。`doctor --ep <本期>` 列出还缺什么。
2. **找视频 + 字幕 + 截图**（浏览器里做）：按 sourcing_bilibili.md。字幕 JSON → `bsub --in sub.json` 生成 `原视频字幕.srt`。
3. **关键点汇总** `关键点汇总.md`：事实 + 原视频时间点 + 截图核对（AI 字幕错字多，以画面为准）。`speechmap` 找「没有官方讲解」的时段，用来留原声。
4. **写稿** `稿子.md`（从本期文件夹里的 `稿子_模板.md` 起手）：先读人物卡/人设档案、术语对照；照 script_format.md 和 hosts_and_footage.md 写；想要看点速报就把第一个板块写成 `## 看点速报`；写完 `parse` 到没有 ⚠。
   接着跑 `stickers`：列出这期要用的表情/动作贴纸，缺的写进 `贴纸需求.md`。**贴纸是整张图（一个表情+动作一张），不分部件、不拼装。**
   ⏸ 把稿子给用户审；`【梗位】` 之类占位和用户讨论定下来；有要新画的贴纸就把需求清单一起给用户。
5. **配音稿**：`dub` → `配音稿/<主播>_配音稿.txt` + `对话顺序对照.md`。
   ⏸ 用户在外部配音，每人一条完整音频 + srt，放进 `配音/`，文件名对上 episode.json。
6. **时间线 + 分镜**：`align`（报「重叠 0 毫秒」才算对）→ `stage`。
7. **截片段**：`clips` 生成 `截片段.ps1` / `.sh` / 清单；本机有原视频就 `clips --cut`；否则 ⏸ 请用户运行脚本。
8. **渲染**：`prepclips` → `audio` → `render --stills 1.5,30,95` 先看几张 → `render`（全片，放后台；中断了 `render --keep`）→ `encode`（成片 + `章节.txt`）。
9. **封面**：`cover` → `成片/封面_16x9.png`、`封面_4x3.png`。
10. **检查**：`qa`，逐条过 qa_checklist.md，亲眼看关键帧拼图、听开头和几处接话。`qa` 会提示哪些贴纸还是占位图。

返工时只从改动的那步往后重跑（qa_checklist.md 末尾有对照表）。

## 3. 固定规则

- 不画官方角色；主播形象只用用户提供的贴纸。贴纸是整张图，一个表情/动作一张，不分部件、不拼装。
- 不用第三方下载站；原视频由用户自己获取，只读，不改动。
- 每句稿子的事实都要能在关键点汇总里找到出处；看点速报只挑本期正片里有的内容，数字不夸大。
- 文件只写进用户连接的项目文件夹；同名旧文件可能正被用户打开，改版时 `encode --tag v2`、`cover --tag v2` 出新文件名。
- 打包给用户的 zip 用 UTF-8 文件名（Python zipfile 会自动标记），否则 Windows 解压中文名会乱码。
- 节目口味（梗多少、原声留不留、要不要 BGM、主播分工）听用户的；定下来的写进 show.json 的 `format` / `audio.orig_rule`，以后每期照做。

## 4. 交付时说什么

一两句：成片几段、多长；封面两张；章节时间点（直接贴 `章节.txt`）；哪些还是占位（贴纸、包装）、需要用户后期补的东西。不复述过程。
